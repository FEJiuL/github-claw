# 赛博梗王内容工作台 · Vibe Coding 路线图

**项目名称**：赛博梗王内容工作台 (Cyber Meme Studio)  
**核心理念**：Vibe Coding —— 先跑通核心情绪价值闭环，再用数据和技术逐步填充细节  
**目标用户**：运营/内容创作者  
**成功标志**：让运营在每个迭代中都能"哇"出来，而不是等半年后的大版本  

---

## 一、分阶段拆分与任务卡片

### Phase 0：手动作坊期（开发前验证，Week 0）
**目标**：无需一行代码，验证内容假设和核心流程。

**Vibe Check**：确认"反向毒鸡汤"的图文形式在目标平台有互动，确认核心闭环有感觉。

| 任务ID | 内容 | 所有者 | 完成标准 |
|--------|------|--------|--------|
| T0.1 | 手动收集10条鸡汤素材 | 运营 | 素材库建立，涵盖人生观/工作观/爱情观等维度 |
| T0.2 | 手动用ChatGPT/Claude生成3种风格的反向文案 | 运营 | 已生成并标记"毒性等级"和"预期感觉" |
| T0.3 | 手动用Canva制作3张海报 | 运营 | 形成"荷花+锦鲤"风格的视觉语言规范 |
| T0.4 | 手动发布到测试账号，记录数据 | 运营 | 小红书/抖音/微博各发3条，记录点赞/评论/分享 |

**交付物**：
- `素材库.xlsx` （10条鸡汤+来源+标签）
- `文案样本.md` （3条反向文案+风格说明）
- `设计规范.md` （色调/字体/排版原则）
- `Phase0-数据记录.csv` （发布数据与互动反馈）

---

### Phase 1：极简流水线（MVP Core，Week 1-2）
**目标**：做出一个"单机版"的工作台，让运营完成"输入金句 → 生成多版本文案 → 复制使用"，并从此上瘾。

**Vibe**："一键出稿的爽感"

#### 卡片拆分

| 卡片ID | 功能名称 | 开发任务 | 验收标准（Vibe Check） |
|--------|--------|--------|--------|
| **C01** | 文本反鸡汤生成器 | 后端API调用LLM，前端一个输入框+风格/毒性下拉菜单+"生成"按钮，返回3个版本的文案。 | 运营输入"人生就像一杯茶，不会苦一辈子"，3秒内看到3条不同风格的拆解文案，觉得"比我自己想的有意思"。 |
| **C02** | 基础文案库 | 将手动收集的爆款文案、金句模板存入本地JSON文件，前端可简单列表浏览和复制。 | 运营能在一个列表里看到历史生成的好文案，快速复制。 |
| **C03** | 简易草稿箱 | 生成结果可保存到浏览器LocalStorage，可查看、删除。 | 关闭网页再打开，之前生成的文案还在。 |

**技术栈**：
- 前端：Vue 3 或 React (Vite)
- 后端：Node.js (Express) 或 Python (FastAPI)
- API：OpenAI GPT-4 (直接调用，无需数据库)
- 部署：Vercel (前端) + Render/Railway (后端)

**交付物**：
- 前后端代码库
- 用户使用指南
- 埋点数据定义文档

### Phase 2：图文合一与分发探路（Week 3-4）
**目标**：让机器能出图，打通"发布"这一环，让运营感受"一键多平台"的效率飞跃。

**Vibe**："从文案到海报的视觉化魔法" & "一键发射的掌控感"

| 卡片ID | 功能名称 | 开发任务 | 验收标准 |
|--------|--------|--------|--------|
| **C04** | 图文海报生成 | 集成文生图API（Stable Diffusion或通义万相），预设3套"中老年荷花/锦鲤"风格LoRA。输入文案，AI生成配图，Canvas合成海报，可下载。 | 运营选择一个文案，点击"生成海报"，5秒内得到一张带有荷花底图、字体为"华文行楷"风格的海报，感觉"就是这个味"。 |
| **C05** | 单平台手动分发助手 | 选择目标平台（小红书/抖音/微博），系统根据格式要求自动生成标题、正文、话题标签。提供一键复制。 | 运营选择文案，选择"小红书"，得到一个格式化内容，复制到小红书App发布顺利。 |
| **C06** | 数据手动录入与看板 | 一个简单表单，运营手动填入发布链接、曝光、点赞等数据。前端展示单条内容的数据趋势图表。 | 运营录入几条数据后，在Dashboard看到内容数据在涨，觉得"一切尽在掌握"。 |

**交付物**：
- C04：图生模型集成方案 + 海报模板库
- C05：各平台格式规范库 + 模板引擎
- C06：数据表单 + 简易BI看板

### Phase 3：感知闭环与半自动化（Week 5-6）
**目标**：接入真实素材源，让数据自动回流，形成"感知-决策-反馈"的智能感。

**Vibe**："系统活起来了，它在帮我找素材、看数据"

| 卡片ID | 功能名称 | 开发任务 | 验收标准 |
|--------|--------|--------|--------|
| **C07** | 素材采集嗅探器 | Python爬虫/API定时抓取指定公众号/RSS/微博的鸡汤类内容，存入数据库，前端展示"灵感流"列表。每条旁有"用这个创作"按钮。 | 每天早上打开工作台，看到"灵感流"里自动多出了10条新素材，感觉"系统晚上也在帮我干活"。 |
| **C08** | 平台数据自动回收 | 对接小红书/抖音开放平台API（或RPA抓取），自动获取已发布内容的后台数据。数据看板实时更新。 | 运营不再需要手动填数据，看板上的数字自己变，能直观看到哪条昨天爆了。 |
| **C09** | 智能选题建议 | 在素材流中，每条素材增加"AI分析"按钮。点击后弹出：建议角度、推荐毒性、预估爆款指数。基于规则+LLM分析。 | 运营对着一条鸡汤素材发愁，点击分析，系统给出"从经济学角度拆解'吃亏是福'"的建议，觉得"这脑洞可以"。 |

**交付物**：
- C07：爬虫/API集成器 + 数据库设计
- C08：各平台API对接方案 + 定时任务管理
- C09：LLM Prompt工程 + 规则引擎

### Phase 4：矩阵分发与数据驱动（Week 7-8+）
**目标**：实现真正的多平台定时自动分发，用数据反哺内容策略，形成飞轮。

**Vibe**："一个人操控一个军团的感觉"

| 卡片ID | 功能名称 | 开发任务 | 验收标准 |
|--------|--------|--------|--------|
| **C10** | 多平台定时分发引擎 | 支持绑定多个账号，设置定时发布任务。使用Playwright/Puppeteer（自动化）或官方API。增强安全检测与重试机制。 | 运营准备好5条内容，分别设定明天早中晚在抖音和小红书发布。第二天早上，内容均已成功发布，收到成功通知。 |
| **C11** | AI策略复盘周报 | 定时任务，每周一自动拉取上周数据，调用LLM生成分析报告。报告可在线查看或导出。 | 周一打开工作台，收到一份图文并茂的周报。运营可直接据此制定本周选题计划，觉得"有个参谋长真好"。 |

## 二、Vibe Coding 实施要点与协作模式

### 2.1 仪式感启动
每个Phase开始，产品、开发、运营一起用30分钟做"Vibe Check"：
- 明确本次迭代我们要追求的"那个感觉"是什么
- 把验收标准写在便利贴上贴到显示器
- 录制一个30秒的"Demo期待"视频，作为团队激励

### 2.2 日构建与体验
- 开发每天至少产出一个可感知的功能点（哪怕只是按钮样式）
- 运营能立刻点一点，给出即时反馈
- 所有反馈在24小时内被纳入下一日的开发计划

### 2.3 运营前置
- 运营**不是**等系统开发完才接入，而是从Phase 1开始就使用最糙的版本
- 所有吐槽和建议都是下个卡片开发的最高优先级
- 产品经理每天和运营做15分钟的"感受反馈"会

### 2.4 数据打点先行
- 从C01开始，所有生成、复制、下载行为都要埋点
- 埋点数据是后续数据分析和策略优化的基础
- 数据规范见：`projects/cyber-meme-studio/docs/埋点规范.md`

## 三、风险控制与降级方案

### 3.1 API成本/不稳定
**问题**：OpenAI API费用高、偶尔超时
**降级方案**：
- Phase 1后台实现"假数据模式"（返回写死的几条爆款文案）
- 开发不依赖API状态，稳定交付
- 后续再切换到真实API

### 3.2 分发风控
**问题**：自动分发可能触发平台风控
**降级方案**：
- 分发引擎永远保留"手动模式"作为降级方案
- 自动分发失败时，自动转为"一键复制+发布指南"推送给运营
- 所有分发操作都有人工审核checkpoint

### 3.3 安全红线
**问题**："毒株"概念可能涉及敏感内容
**降级方案**：
- Phase 2引入"毒性"概念时，硬编码敏感词过滤列表
- 宁左勿右，所有灰色内容都默认过滤
- 定期与法务/安全团队sync
